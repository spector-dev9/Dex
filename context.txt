----------------------------

  16 KB-page devices, multi-device matrices.

5. Android SDK setup
--------------------
The full Android SDK is not currently configured. To build locally, install
Android command-line tools from the official Android developer download page:

  developer.android.com/studio#command-tools

Do not invent or guess a versioned download URL. Download the current
Linux command-line tools zip, then install it under $HOME/android-sdk:

  mkdir -p "$HOME/android-sdk/cmdline-tools"
  unzip commandlinetools-linux-*.zip -d "$HOME/android-sdk/cmdline-tools"
  mv "$HOME/android-sdk/cmdline-tools/cmdline-tools" \
     "$HOME/android-sdk/cmdline-tools/latest"

  export ANDROID_HOME="$HOME/android-sdk"
  export ANDROID_SDK_ROOT="$ANDROID_HOME"
  export PATH="$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"

  yes | sdkmanager --licenses
  sdkmanager "platforms;android-36" "build-tools;36.0.0"

The Android Gradle build requires:
- compileSdk 36
- build-tools 36.0.0
- JDK 21
- For the harness: NDK 27.2.12479018 and CMake 3.22.1

Create local.properties if needed:

  sdk.dir=/data/data/com.termux/files/home/android-sdk

On aarch64 Termux, the x86_64 aapt2 downloaded by Gradle cannot execute.
Use the Termux aapt2 as an override for local app builds:

  ./gradlew --no-daemon \
    -Pandroid.aapt2FromMavenOverride=$PREFIX/bin/aapt2 \
    :app:assembleDebug

A previous local :app:assembleDebug succeeded with this override in about
4.5 minutes. That does not prove the native harness build works locally.

6. Building the spike harness
-----------------------------
The harness is a separate debug APK. It contains test-only native helpers,
the pinned Alpine/PRoot runtime, and S1/S3/S7/S8 probes. It is not the
production app.

Recommended path: build in GitHub Actions, because this Termux host has no
NDK and the official NDK host toolchain is x86_64. The workflow installs
platform 36, build-tools 36.0.0, NDK 27.2.12479018 and CMake 3.22.1.

Before compiling any harness build, stage the pinned runtime:

  cd /data/data/com.termux/files/home/mkd/remote-check
  python3 scripts/stage-spike-harness.py

Staging downloads and SHA-256-verifies the pinned artifacts, then creates:
- runtime/artifacts/spike-runtime.tar.gz
- tests/spikes/harness/src/main/jniLibs/arm64-v8a/libldmusl.so
- tests/spikes/harness/src/main/jniLibs/arm64-v8a/libproot.so
- tests/spikes/harness/src/main/jniLibs/arm64-v8a/libproot_loader.so
- additional packaged runtime libraries

The jniLibs and runtime artifacts are gitignored. Re-run staging after a
clean checkout.

Local harness build command, only with a working SDK + NDK + CMake:

  ./gradlew --no-daemon \
    -Pandroid.aapt2FromMavenOverride=$PREFIX/bin/aapt2 \
    -PspikeHarness=true -PskipApp=true \

8. Startup crash: cause and fix
-------------------------------
Crash files:
  /storage/emulated/0/download/crash-report-20261026-085752.txt
  /storage/emulated/0/download/harness-crash-20261026-085731.txt

Exception:
  java.lang.NullPointerException:
  Attempt to do a synchronize operation on a null object
  at ImeProbeEditText.record(ImeProbeEditText.kt:152)
  at ImeProbeEditText.onSelectionChanged(ImeProbeEditText.kt:110)
  at android.widget.TextView...<init>
  at ImeProbeEditText.<init>
  at MainActivity.buildUi

Root cause:
Android's EditText superclass constructor calls onSelectionChanged() while
the ImeProbeEditText constructor is still running. Kotlin instance field
initializers (eventTrace and eventTraceLock) run after the superclass
constructor. Therefore record() saw eventTraceLock == null and synchronizing
on it threw NullPointerException.

Fix applied in commit 4d35a17:
- Added private var traceReady = false.
- Set traceReady = true in an init block, after all field initializers.
- record() now returns immediately while traceReady is false.

Relevant code shape:

  private var traceReady = false

  init {
      traceReady = true
  }

  private fun record(event: String) {
      if (!traceReady) return
      lastEvent = event
      synchronized(eventTraceLock) {
          ...
      }
      post { eventListener?.invoke(event) }
  }

Why this is safe:
- Only construction-time internal callbacks are dropped.
- No user keyboard event occurs before the view is attached and interactive.
- Counters and normal tracing remain active after construction.
- Do not "fix" this by only making eventTraceLock nullable; eventTrace is also
  uninitialized during the superclass constructor.

Rebuild and verify:

  gh run watch <run-id> --repo vector-dev9/Opencode-mobile
  gh run download <run-id> --repo vector-dev9/Opencode-mobile \
    -n app-apks -D /data/data/com.termux/files/usr/tmp/opencode/ci-rebuild

  adb install -r \

9. Other known issues and troubleshooting
-----------------------------------------
A. Missing local Android SDK / NDK
   Symptom: Gradle cannot find android.jar, aapt2, NDK or CMake.
   Fix: install the SDK as in section 5, use the aapt2 override, or use CI.
   The harness native build is best treated as CI-only on this host.

B. aapt2 executable format error
   Symptom: "cannot execute binary file" or Exec format error.
   Cause: Gradle downloaded an x86_64 aapt2 for aarch64 Termux.
   Fix: use -Pandroid.aapt2FromMavenOverride=$PREFIX/bin/aapt2.

C. check-provisional.py fails with "no compiled core classes"
   Run the core compilation first:
     ./gradlew --no-daemon -PskipApp=true coreCheck
     python3 scripts/check-provisional.py

D. Node tests fail before dependencies are installed
   Run:
     npm ci
     npm run typecheck
     npm test

E. Shallow clone push failure
   Symptom: "remote unpack failed: index-pack failed" or
   "did not receive expected object".
   Fix:
     git fetch --unshallow https://github.com/spector-dev9/Opencode-mobile.git main
   The current clone already has full history.

F. Push to spector-dev9 fails with 403
   Use origin, which points at vector-dev9/Opencode-mobile. Never change the
   remote to a read-only repository and never embed a token in the remote URL.

G. Stale helper path
   /data/data/com.termux/files/usr/tmp/opencode/run-harness.sh still contains
   an old /home/GP/opencode-mobile path and old probe labels. Update the TAR
   path and action labels before using it for automation.

H. Runtime is missing or S1/S3 fail with missing loader
   Re-run:
     python3 scripts/stage-spike-harness.py
   Manual fallback:
     adb push runtime/artifacts/spike-runtime.tar.gz /data/local/tmp/

       sh -c 'cd files && tar xzf /data/local/tmp/spike-runtime.tar.gz'

I. Old crashing APK remains installed
   Reinstall the new APK with adb install -r. If the signing key differs,
   uninstall first:
     adb uninstall io.github.spectordev9.opencode.spike.debug

J. README contradiction
   tests/spikes/harness/README.md says CI does not stage the harness, but
   .github/workflows/ci.yml does run scripts/stage-spike-harness.py.

K. G0 scope documentation commit

13. Security rules for this context file
----------------------------------------
Never write any of the following into context.txt or committed files:
- GitHub personal access tokens
- npm tokens
- server passwords or provider API keys
- Android keystore contents or passwords
- SSH private keys
- device ADB pairing codes

Use gh auth for GitHub operations. Do not put credentials in git remote URLs.
Cleartext networking in the debug harness is test-only loopback behavior and
must not be copied into production.
